## Commodity mechanism

A work unit may request distributed model inference through capabilities, model capacity, privacy, validation, performance, wall-time, and authority requirements. It cannot name SwarmLLM or any other supplier. Supplier identity exists only beneath a replaceable adapter implementing `axm/distributed-model-inference@1`.

A distributed formation is evaluated as one composite route only when it carries an executable adapter, a supported partition mode, unique member-seat references, current availability, formation-capacity and topology receipts, a privacy declaration, member-drop behavior, performance evidence, and the validators required by the work unit. This version admits `pipeline-layer` as the supported partition mode.

Independent routes remain independently sufficient or insufficient. Their memory is never summed. A composite route may expose `modelCapacityBytes` only as a measured property of the executable formation. Member memory pledges are consistency ceilings. They are not evidence that the formation can execute the model.
